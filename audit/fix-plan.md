# Nedmori 修复计划

依据：2026-09-27 浏览器巡查报告。当前阶段：修复与回归完成。

目标：修复已复现的问题，让信息更易读、手机端能直接看到关键结果、做题流程更连贯。保留现有品牌、浅深配色、Lako 组件和已有数据。

## 1. 修复功能与数据说明

- [x] 搜索同时兼容 `P1001`、`p1001`、`1001` 和首尾空格，保留标题及算法搜索。
- [x] 明确提交的实际状态：当前仅保存代码，判题尚未接入；提交前、提交结果与记录详情表达一致。
- [x] 区分示例历史、后端保存、浏览器暂存，避免把 server 记录统一称为本机记录。
- [x] 给示例榜单、个人统计、活动和比赛提供简洁的数据来源说明，避免把固定数据呈现为实时结果；每日一题固定内容使用准确名称。
- [x] 明确排行榜“本周变化”的指标与单位；没有题数变化数据时不显示伪造的题数变化。
- [x] 统一提交记录日期格式。

验收：四种题号输入均命中同一题；既有搜索仍正确；用户无需阅读 README 就能理解提交是否会被判题；数据标签与实际存储来源一致。

## 2. 修复手机布局与信息顺序

- [x] 收藏按钮禁止被压成竖排；窄屏使用紧凑且有明确无障碍名称的布局。
- [x] 提交记录在窄屏优先显示题名、状态、时间。长编号缩短展示，完整编号保留在详情中。
- [x] 排行榜在窄屏优先显示名次、用户、当前排序指标，其他数据降为次要信息。
- [x] 检查题目标题、筛选条、编辑器工具栏、弹窗及移动菜单，处理长文本和 320px 边界。
- [x] 算法下拉菜单提供搜索及可继续滚动的线索，确保尾部算法容易找到。

验收：320px、390px 下收藏不换行；不横滑也能看到提交状态和当前排名指标；无整页横向溢出；菜单、弹窗可完整操作。代码和必要的长内容允许在自己的区域内横向滚动。

## 3. 统一阅读层级与页面比例

- [x] 以题库为基准调整字体层级：常用辅助信息优先采用 12–13px，避免重要数据依赖 9–10px 小字。
- [x] 提高浅深主题辅助文字的对比度，区分正常次要信息、占位文字和禁用状态。
- [x] 将题库行距适度收紧，起始目标约 72–80px；根据实际两行内容和手机点击区域调整。
- [x] 题库保留任务相关侧栏；比赛与排行榜减少重复公告，让主内容使用合适的阅读宽度。
- [x] 个人页热力图采用有上限的格子尺寸，增加日期参照，让统计与最近活动保持主次关系。
- [x] 精简泛化鼓励文案，优先呈现当前筛选、统计口径和数据来源。

验收：浅深主题下表头、题号、时间与次数无需费力辨认；各页对齐与间距一致；1440px 不过度拉伸，768px 折叠合理；保持现有视觉风格。

## 4. 修复导航与做题流程

- [x] 去掉头像入口的误导性下拉箭头，保持直接进入个人页的现有行为。
- [x] 比赛进入题目时保留来源，提供返回当前比赛的入口；直接从题库进入仍返回题库。
- [x] 题内空提交历史改为引导“提交解法”，直接切到当前题目的代码区。
- [x] 收藏成功后使用“已收藏”等清晰反馈，并保持状态可被辅助技术识别。
- [x] 为 textarea 补齐 Tab / Shift+Tab 缩进与清晰的键盘退出方式；保持现有草稿键值与内容兼容。
- [x] 桌面和窄屏均按“题目描述／提交代码／提交记录”标签单独显示内容；切换不丢草稿与语言。
- [x] 页面路由与题内标签切换加入淡入过渡；不支持原生 View Transitions 时使用 CSS 回退，并尊重减少动态效果设置。
- [x] 题库、比赛、提交记录、排行榜切换顶部导航或各自页内 Tab 时，让新列表条目以 8px / 240ms 的 fadeSlideIn 和 30ms 交错进入；保留在新列表里的条目也重播动画，不做共享变形。
- [x] 从列表进入单题页时，让题目内容整体轻微上移淡入；返回列表时继续使用列表行交错入场。
- [x] 题内标签仅对内容区做淡入，避免整页过渡快照与组件指示条同时绘制造成双横线。
- [x] 调整编辑区高度及操作区，使提交操作容易找到，避免遮挡最后一行代码、弹窗或软键盘区域。

实现约束：先沿用现有 textarea 和组件；本轮不引入重型编辑器依赖，不扩展自动补全、调试器或真实判题系统。

验收：比赛来路可恢复；空状态不把用户带离题目；缩进和键盘退出都可用；题面/代码切换、语言切换和刷新后草稿保留；桌面题面与代码按标签切换，互不混入。
